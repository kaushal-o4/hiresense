# HireSense AI: API Documentation

The backend is a **FastAPI** application (`backend/app/main.py`). It exposes **203 HTTP endpoints**, all under `/api`
(GET 90, POST 74, DELETE 17, PUT 15, PATCH 7). This document was generated from the route decorators in the code
and cross-checked against FastAPI's own OpenAPI schema: both list exactly the same 203 method + path pairs.

You can also explore every endpoint interactively while the backend runs, at **http://127.0.0.1:8000/docs**
(Swagger UI, generated by FastAPI).

## How to read this document

- **Authentication.** After `POST /api/auth/login` the server sets an httpOnly cookie `hs_session` that holds a
  signed JWT. Browsers send it automatically. API clients may send `Authorization: Bearer <token>` instead. "Who
  can call it" names the FastAPI dependency the endpoint uses:
  - `require_student`, `require_recruiter`, `require_mentor`, `require_admin` allow one role only
  - `get_current_user` allows any signed-in user
  - endpoints without a dependency are public
- **Request body.** Each body is a Pydantic model from `backend/app/request_validation_schemas.py` (or a small
  model defined in the route file). Invalid input gets **HTTP 422** with field-level messages.
- **Errors.** Errors come back as `{"detail": "message"}`. Common codes:
  - 401: not signed in
  - 403: wrong role or no access
  - 404: not found, or not yours
  - 409: duplicate
  - 428: hosted-AI consent required
  - 429: rate limited or locked out
  - 503: AI unavailable. The app never invents an AI result.
- **Database.** Lists the MongoDB collections the route file references *directly* (including its helpers in the
  same file). Shared helpers in `services/` may touch more, for example `audit_logs` (through `audit()`) and
  `notifications` (through `notify()`).
- **AI / speech service.** Says whether the endpoint calls the language model (Google Gemini or local
  Ollama `qwen3:4b`), Whisper speech-to-text or Kokoro text-to-speech.
- **Streaming endpoints** send Server-Sent Events (`text/event-stream`):
  - `POST /api/student/interviews/{id}/turn` (live voice interview)
  - `POST /api/student/english/{id}/message/stream`
  - `GET /api/notifications/stream`
  - `POST /api/voice/speak/stream`, which sends one JSON line per sentence

## Most important endpoints (the interview journey)

| Step | Endpoint | Used by (frontend) |
|---|---|---|
| Register | `POST /api/auth/register/student` | `pages/Register.jsx` |
| Login | `POST /api/auth/login`, then `GET /api/auth/me` | `pages/Login.jsx`, `AuthContext.jsx` |

## Endpoints that have no screen in the frontend yet

These endpoints exist and are covered by the backend tests, but no page in `frontend/src` calls them, so they can
only be used through the API (for example Swagger at `/docs`):
- `POST /api/recruiter/jobs/{job_id}/screen` (bulk AI screening)
- `GET /api/recruiter/jobs/{job_id}/export` (CSV export)
- `GET` and `POST /api/recruiter/applications/{application_id}/messages`, plus the student-side
  `GET` and `POST /api/student/applications/{application_id}/messages` (application messages)
- `POST /api/recruiter/applications/{application_id}/assessments` (assign a test to an applicant)
- `GET /api/mentor/report`, `GET /api/mentor/students/{student_id}/report` (mentor CSV reports)
- `POST /api/mentor/students/{student_id}/remedies/assign`

(Found by searching `frontend/src` for each path on 2026-11-14.)

# Complete endpoint reference

### `backend/app/main.py`

#### 1. `GET /api/health`

- **Purpose:** Health.
- **Who can call it:** Public (no login)
- **Backend function:** `health()`
- **Database:** none directly
- **AI / speech service:** none
- **Response:** JSON object with keys: `status`, `app`

#### 2. `GET /api/health/live`

- **Purpose:** The process is up. Never touches the database or the model, so an orchestrator can use it to decide whether to restart the process.
- **Who can call it:** Public (no login)
- **Backend function:** `liveness()`
- **Database:** none directly
- **AI / speech service:** none
- **Response:** JSON object with keys: `status`

#### 3. `GET /api/health/ready`

- **Purpose:** Whether the app can serve requests. The database is required (503 if it fails). The AI parts are reported per component but never make the app 'not ready': the app is designed to keep working, with clearly labelled reduced features, while Ollama or a voice model is unavailable. No user data or file paths are returned.
- **Who can call it:** Public (no login)
- **Backend function:** `readiness()`
- **Database:** none directly
- **AI / speech service:** language model client
- **Response:** File / raw response (JSONResponse)
