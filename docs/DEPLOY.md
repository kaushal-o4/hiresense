# Deploying the HireSense demo (MongoDB Atlas + Render + Vercel)

This puts a public demo online on free plans: the **database** on MongoDB Atlas, the **API** on Render, the **web
app** on Vercel. The hosted API uses the *cloud profile*: Google Gemini answers the AI requests, the interviewer
speaks with the browser's built-in voice, spoken answers are transcribed by Gemini and job matching uses skills and
keywords. The local models (Ollama, Whisper, Kokoro, sentence embeddings) need a GPU laptop and are not used here.

```
browser ──► https://<app>.vercel.app            (React build, static files)
               └─ /api/*  ──rewrite──► https://<api>.onrender.com/api/*   (FastAPI, Docker)
                                            ├─► MongoDB Atlas (M0)
                                            └─► Gemini API (Google)
```

The browser only ever talks to the Vercel domain, so the login cookie is first-party (`SameSite=Lax`).

## What you need

| Account / value | Where | Cost |
|---|---|---|

| MongoDB Atlas account | https://www.mongodb.com/cloud/atlas/register | free M0 cluster (512 MB) |
| Render account (sign in with GitHub) | https://render.com | free web service |
| Vercel account (sign in with GitHub) | https://vercel.com | free Hobby plan |
| Gemini API key | https://aistudio.google.com/apikey | free tier with rate limits; paid beyond it |
| A strong admin password | you choose | |

## 1. Database: MongoDB Atlas

1. Create a project, then **Build a database → M0 (Free)**. Pick a region near Render's (AWS Mumbai or Singapore).
2. **Database Access → Add new database user**: username `hiresense`, a generated password, role
   *Read and write to any database*.
3. **Network Access → Add IP address → Allow access from anywhere (`0.0.0.0/0`)**. Render's free plan has no fixed
   outgoing IP, so the user/password is the protection. Use a long generated password.
4. **Database → Connect → Drivers** and copy the connection string, e.g.
   `mongodb+srv://hiresense:<password>@cluster0.abcd1.mongodb.net/?retryWrites=true&w=majority`.
   Put the real password in (URL-encode `@ : / ? #` if it has any).

## 2. Gemini key

Create a key in Google AI Studio. Set a budget/quota alert in Google Cloud if billing is on: every interview turn,
resume analysis and spoken answer is a request. The demo caps each user at `AI_DAILY_LIMIT_PER_USER=60` AI calls a day.

## 3. API: Render

1. Push the repository to GitHub.
2. Render → **New → Blueprint** → choose the repository. Render reads `render.yaml` and creates `hiresense-api`
   (Docker, free plan, Singapore). It asks for the values marked `sync: false`:
   - `MONGODB_URL`: the Atlas string from step 1
   - `GEMINI_API_KEY`: from step 2
   - `ADMIN_PASSWORD`: the first admin's password (login `admin@hiresense.app`)
   - `FRONTEND_URL` and `CORS_ORIGINS`: the Vercel address. You don't know it yet: enter
     `https://hiresense.vercel.app` (or your chosen project name) and correct it after step 4.
   - `REDIS_URL`: leave empty (one instance)
   `SECRET_KEY` is generated by Render.
3. Wait for the deploy, then open `https://<api>.onrender.com/api/health/ready`. Expected:
   `"database": {"ok": true}`, `"language_model": {"ok": true}`, and `speech_synthesis`/`embeddings` listed as
   degraded. Those two are off on purpose in the cloud profile.
4. Each start runs `python -m app.seed` (safe to repeat): it creates the admin account, badges and the question bank.

## 4. Web app: Vercel

1. Edit `frontend/vercel.json` and replace `REPLACE-WITH-YOUR-API.onrender.com` with the Render host from step 3.
   Commit and push.
2. Vercel → **Add New → Project** → import the repository → **Root Directory: `frontend`**. The framework preset is
   Vite. No environment variables are needed. Deploy.
3. Put the final `https://<project>.vercel.app` address into Render's `FRONTEND_URL` and `CORS_ORIGINS` and redeploy
   the API.

## 5. Check it

1. Open the Vercel URL and sign in as `admin@hiresense.app`. Change the password in Account settings if you used a
   temporary one.
2. Register a student. The register form shows the optional "processed by Google Gemini" checkbox. Leave it
   unticked: the interview page must show the AI data notice, and starting an interview must be refused until you
   click **I agree**.
3. Start a **live voice interview** in Chrome or Edge. The interviewer speaks with the browser voice. Answer out
   loud: the text appears after each pause. There are no live word-by-word captions with Gemini speech recognition.
4. Check `/privacy`.

## Option B: frontend calls the API domain directly

Use this if the Vercel rewrite gives you trouble (see the limits below). In this option the browser sends the
cookie to `onrender.com` itself:

- Vercel: set the environment variable `VITE_API_URL=https://<api>.onrender.com` and remove the `/api` rewrite from
  `vercel.json`.
- Render: set `COOKIE_SAMESITE=none` (Secure is forced on) and `CORS_ORIGINS=https://<project>.vercel.app`.

Browsers that block third-party cookies (Safari, and Chrome with that setting on) will then not keep the login. That
is why option A is the default.

## Option C: one server with Docker

```
cp .env.docker.example .env.docker     # fill in MONGO_PASSWORD, SECRET_KEY, GEMINI_API_KEY, ADMIN_PASSWORD
docker compose --env-file .env.docker up -d --build
```

This starts MongoDB (with a password, not exposed to the host), the API and nginx on `http://localhost:8080`. Put an
HTTPS reverse proxy (Caddy, Traefik, a cloud load balancer) in front and set `COOKIE_SECURE=true` and
`FRONTEND_URL=https://your-domain`.

## Known limits of the free demo

- **Cold starts:** a free Render service sleeps after 15 minutes idle. The first request then takes about a minute.
  If Vercel's proxy gives up first, reload the page.
- **Not verified yet on the real services:** streamed interviewer replies (Server-Sent Events) and uploads of
  around 4–5 MB through Vercel's external rewrite. Try one live interview and one resume upload right after the first
  deploy. If either fails, switch to option B.
- **Uploaded resume files** live on the Render instance's temporary disk and are lost on restart or redeploy. The
  extracted text and the analysis stay in MongoDB, so the app keeps working, but "Download resume" fails for older
  uploads. Attach a Render disk at `/data` and set `UPLOAD_DIR=/data/uploads` to keep them.
- **One instance:** login lockout and rate limits are in memory unless `REDIS_URL` is set. Set it before running more
  than one instance.
- **Atlas M0:** 512 MB storage and shared CPU. Fine for a demo, not for a whole college.
